# MiniMax-H3-Image on the Mac: fast mode with a half-canvas draft start

- `tf-h3-image` and `tf-h3-image-server` grew `--draft-steps N` (and `--renoise-sigma X`), the Metal port of the Spark's opt-in fast mode (card 131): the first N steps run on the half-size canvas through a second `.h3case` binding, `cascade.lift` predicts the clean latent `x + σ·v` from the last draft step's video and velocity, upsamples it bilinearly and renoises it to the next sigma with the seed's own detail, then the rest of the steps redraw at full size. `cascade.pool` draws the draft's half-grid noise from the seed's full draw so both canvases share one seed's picture.
- Metal needs no kernels for it: per-step output heads live in the case file, so an off-grid step's head is the blend (`picture.headSpan`, mmh3's `step_heads`) written host-side into `video_out.weight`/`bias` by `Case.write`'s new `Plan` — the same struct overrides the run's schedule, target grid and noise for the draft's case. `Folder.bind` takes the plan's schedule and reschedules the bound model's AdaLN lines and step tables through `modulation.reschedule`.
- Drafts are render-only: `once` with `--draft-steps` is an error, the teacher-forced and latent gates skip (a draft draws a *different* picture on purpose), and cases with reference rows refuse with `H3DraftWithReferences`, as the CUDA path does. Canvases whose latent grid doesn't halve cleanly refuse with `H3BadCascadeGrid` (a canvas side must be a multiple of 64 px).
- Measured warm on this Mac (M5 Ultra, 2048x2048, seed-42 fox prompt, ReleaseFast): six timing-valid steps take **10.4 s**; with `--draft-steps 3` the same six steps take **6.3 s** — three half-size steps at 0.5 s each plus three full-size at 1.6 s GPU each, a ~40% cut matching the Spark's 15.3 → 10.7 s. The draft's latent cosine against the six-step run is **0.70** (a second six-step run's is 0.995), consistent with the Spark port's 0.706; the side-by-side PNG is in `docs/recipes/minimax-h3-image-metal/draft-vs-six-step.png`.
- Tests: `h3_image_server.zig` covers `draftPlan`'s pooled noise against `cascade.pool` directly, two deterministic `drafted` runs, a renoise plan's blended heads, and every refusal (`H3BadDraftSteps`, `H3DraftLeavesNoStep`, `H3BadRenoiseSigma`, `H3BadCascadeGrid`).
