# Checkouts stay small: Zig cache and staged files outside the tree

- Card checkouts reached 15-17 GB (78.4 GB for 13 on 23 November); measured, everything but ~0.2-0.6 GB per checkout was its `.zig-cache/o`: 1,300+ stale `test` binaries and 69 MB `test_zcu.o` objects, one set per revision built, which Zig never prunes. No checkout held model weights; card 178 held a 381 MB ad-hoc `.h3-178-job` folder.
- Zig 0.17 picks the local cache before `build.zig` runs. `tools/zig/setup_cache.sh` links each card checkout's `.zig-cache` to the shared external folder and its `zig-out` to that checkout's own folder there before the first build, so even plain `zig build` stores objects, test scratch and installed Metal/CUDA outputs outside it. The setup refuses existing folders rather than losing them, concurrent runs agree on one link, and an existing link must match byte for byte, so one whose target only adds a trailing newline is refused.
- `tools/zig/{bf16_topk,draft_ops,tree_round}_build.sh` and `tools/release/check_package.py` (`test-dist-package`) follow `ZIG_LOCAL_CACHE_DIR` and default to the external `$HOME/.cache/tensorfold/zig` even before setup. They and the setup share `tools/zig/outside_checkout.py`, which refuses a cache that is the checkout or inside it by filesystem identity, so symlinked or case-variant spellings are caught too, and refuses a path containing a newline, which shell command substitution would strip. The three standalone scripts put explicit executables in per-checkout paths to avoid collisions across simultaneous builds.
- `tools/zig/check_mlx_ops.py` compiles its Metal runner and stages its weight tensors in the checkout's folder of the shared cache instead of `build/zig-ops`, so an aborted run leaves nothing in the tree, and its sibling imports write no bytecode (the checker's own is written before its flag can run). `tools/zig/test_fabric.sh` builds its link test, MCDMA libraries and Zig caches there too, without setup first, and `tools/zig/cuda_sass_compare.py` (`sass_compare.sh`) retains its snapshots under `sass-compare/` in the shared cache unless `--output` names a folder. The `tools/zig/xpu_fixtures_*.py` generators default `TF_FIXTURES_DIR` to `$HOME/tensorfold-fixtures`, where the XPU tests read them, instead of a checkout-relative folder.
- AGENTS.md makes that setup the first step of every card build. CONTRIBUTING.md documents it and weights/GGUF/fixtures/job output outside the tree; the native recipes skill points to it.
- `tools/zig/setup_cache_test.py`, invoked by `zig build test` on macOS and Linux (the scripts are POSIX shell), checks a default build and all direct entry points without overrides, rejects in-checkout caches (canonical, symlinked, case-variant, newline-suffixed directly or through a symlink), symlinked outputs and an existing link whose target adds a trailing newline, checks every entry point refuses an in-checkout cache and leaves no sibling bytecode in the checkout, checks the Metal checker, the fabric tests, the SASS comparison and the fixture generators write outside the checkout by default, runs setup concurrently, and builds the three tools from two checkouts at once.
- Exact prefetch span allocation avoids Zig's heap-layout-dependent `toOwnedSlice` shrink; its allocation-failure host test also passes when the external cache path resolves to 56 characters.
