# MiniMax-H3-Image on the Spark: fuse the transformer's elementwise passes like mmh3

- `docs/mmh3-h3-image-study.md` lever 2: mmh3's transformer runs one preprocessing launch a block — gated residual add, modulated RMSNorm, Hadamard rotate and quantize in one pass; our int8 path ran `h3_norm` + `h3_quantize` before the qkvc product, `h3_dequantize` + `h3_heads` after it, and `h3_swiglu_int8` + `h3_dequantize` around fc1 — ~3.2 s of elementwise launches a picture against mmh3's 1.34 s fused.
- `h3_norm_quant` folds the gated add, modulation and quantize into one launch (the normed row staged once in shared so `quantize_chunks` reads it without a global round trip); `h3_heads_i8` reads the qkvc product's int32 sums and scales and runs `h3_heads`' q/k RMSNorm + split-half rotary on the dequantized values — once per row, not per tile pair (card 120's fold-into-attention measured 11x slower). `h3_swiglu_int8` already folds `silu(gate)*up` into fc1's epilogue. The bf16 path and the clip forward are unchanged.
- Both fusions keep the launch they fold's arithmetic: `h3_norm_quant` reuses `h3_norm`'s thread stride, `block_sum_serial` squares and `modulated` rounding, then `h3_quantize`'s absmax/rounding verbatim; `h3_heads_i8` rounds each dequantized value exactly as `h3_dequantize` does (`bf(acc*sx*sw)` on the product's f32 scale) before the identical head loop. Output is bit-identical to the unfused chain — verified by the new `fused_test` device regression in `tf-h3-image-cuda --self-test` and by sha256-identical latents in the same-job A/B.
