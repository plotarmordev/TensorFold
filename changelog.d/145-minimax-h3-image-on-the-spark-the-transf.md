# MiniMax-H3-Image on the Spark: the transformer's fused passes at load width

- Card 128's fused `h3_heads_i8` regressed `heads` 0.96→1.40 s a picture: holding a lane's 32 q and 32 k values as floats took 252 registers and spilled to local memory. The kernel now keeps q and k rounded to bf16 two a word — bit-identical values, half the live registers — reads every row 16 bytes at a time, and recomputes the rotary partner's dequantized values from a second `int4` load of the partner's `int32` group rather than shuffles or shared arrays (card 88's wider loads alone measured 2x slower; card 120's fold into attention 11x).
- `h3_swiglu_int8` (0.83 s) moves from a grid-stride element loop to one block a row of 4-wide `int4`/`float4` groups — the same dequantize, silu and product, each row's int32 sums read once and the bf16 act written once, eight bytes a store. The bit-identical-output requirement rules out int8 act rows: cuBLASLt's mixed bf16×i8 path can read the codes but has no epilogue for the row scale, so fc2's product would change.
- `fused_test` covers the whole chain byte-for-byte: `h3_norm_quant`, `h3_heads_i8` and `h3_swiglu_int8` each match `h3_norm`+`h3_quantize`, `h3_dequantize`+`h3_heads` and `h3_dequantize`+`h3_swiglu`. Latents stay byte-identical; the same-job A/B (`bench-145-ab.sh`) measured the stage times in `docs/recipes/minimax-h3-cuda.md`.
