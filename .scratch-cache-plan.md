# Card 127 plan — prompt-state cache in tf-h3-image-prompt-cuda --serve

## Facts (scouted)

- Server loop: `zig/tests/h3_image_prompt_cuda.zig` `serve()` :113-144, worker `pictureRun` :148-179.
- Per request: prompt file read + strip (1.5 ms), `rules.present` (~1.5 ms), `rules.positions`, then `runner.encode` (~0.9 s) + `runner.refine` (~0.2 s) = the 1.1 s `prompt:` line. `stage.write` + file write ~10-20 ms.
- `--serve` never passes references/vision; `present`/`positions` called with `&.{}`. No CFG/negative/template exists anywhere in the family.
- Text rows `text: []u16` T*5376 bf16 is the consumed state; `p.ids`/`p.tags`/`at` (empty) also land in the case.
- Geometry (`enc.text`, `front`, `marks`, tokenizer, segment_tokens) fixed per process from checked configs; key = stripped prompt bytes. Cross-model harmlessness enforced by clearing the cache when the arena-prompt `T` changes (see below).
- ~2-3 MB per entry at T<=4096 (22 MB max); GB10 unified memory is one pool — every cached MB sits next to ~100+ GiB resident weights. Budget 256 MiB default, env override.

## Design

New file `zig/src/families/h3/prompt_cache.zig` (family-internal; owned dir):

```zig
//! The resident prompt server's kept states: a prompt's refined text rows across pictures.
const std = @import("std");

pub const default_bytes: usize = 256 << 20;

/// One prompt's states: its presentation (ids and tags) and the refiner's text rows.
/// Owned slices; `bytes` counts them toward the budget.
const Entry = struct {
    key: []u8,          // the prompt bytes, exactly as tokenized
    ids: []u32,
    tags: []i32,
    text: []u16,
    bytes: usize,
    used: u64,
};

pub const Cache = struct {
    gpa: std.mem.Allocator,
    entries: std.ArrayList(*Entry),   // LRU order: oldest first
    bytes: usize = 0,                 // held across entries
    budget: usize,
    hits: u64 = 0,
    misses: u64 = 0,

    pub fn init(gpa, budget) Cache
    pub fn deinit(c: *Cache) void                      // frees every entry
    /// The prompt's kept presentation and text rows, its entry made newest.
    pub fn find(c: *Cache, key: []const u8) ?struct{ ids: []const u32, tags: []const i32, text: []const u16 }
    /// `text` (and ids/tags) kept for `key`; evicts least-recently-used until it fits.
    /// Entries larger than the budget are not kept.
    pub fn keep(c: *Cache, key: []const u8, ids: []const u32, tags: []const i32, text: []const u16) !void
};
```

- `find` moves the entry to the back (newest). `keep` duplicates the slices into gpa-owned storage and inserts newest; on duplicate key it replaces (same prompt => same rows; replacing keeps `keep` idempotent after a failed request).
- Eviction loop in `keep`: while bytes + need > budget and entries nonempty → drop front entry.
- The cache borrows nothing from the request arena: all entry storage is gpa-owned so it survives `request.deinit()`.

## byte-identical-picture test

A `zig build test` host test can't run CUDA. But the case write is host-deterministic given identical (p, text, request, seed draws). The CPU test asserts:
- keep→find returns slices byte-equal to inputs (trivially true — same bytes). The real claim "cached states byte-identical to fresh encode" is proven by: (a) encode is deterministic (existing selftest gate on TOP), (b) the cache stores the encode's output slice verbatim and returns it verbatim (unit test asserts the returned slice bytes equal the stored bytes — same memory, so tautological). The meaningful check: on a hit the case file is byte-identical — test `stage.write` twice with same (p,text,request) → identical bytes? prompt_case_test already pins write output byte-for-byte. The real end-to-end evidence is the TOP run: repeated-prompt PNG byte-identical to main's (compare sha256 of PNGs between runs — the bench's SUMMARY reports; do the diff on TOP after the job).
